# Public v2 overhaul — September 6, 2026

The public project needed a coherent developer entry point and a current account of KAIOS. The 0.1 repository mixed character writing, experimental consciousness mechanisms, CLI tools, guessed product APIs and music engines behind one root import. Some advertised subpaths were absent from the build. The local strict typecheck had 13 errors, and frame-call timing changed musical structure.

## Design choice

Three approaches were considered: rewrite around an agent framework, refresh documentation alone, or retain the working engines while introducing portable contracts. This preview takes the third approach. It carries the current character and product direction into runnable modules, preserves historical material, and makes the connections to heavier services explicit.

The new surface consists of an application-owned character definition, a small runtime, a Unicode expression vocabulary/grammar, a versioned affect bus, a voice capability seam and the existing substrate adapter. The legacy runtime remains available for comparison. New imports have no account, model, retention or playback side effects.

## Implementation and review

1. Preserve baseline Git history and untracked design material; create an isolated branch from the recorded remote revision.
2. Carry the September 4 elapsed-time clock candidate as a separate commit; preserve the legacy engine.
3. Add portable character/runtime, consent and forget ordering, injected text/voice adapters, canonical availability rules and immutable affect ownership.
4. Extract only public-safe deterministic expression rules; preserve Unicode and leave personal corpora and product accounts outside the package.
5. Repair type errors, exports and dependency configuration; test the actual packed artifact in ESM, CommonJS, TypeScript and browser bundling.
6. Consolidate concept, lore, writing, ecosystem and API documentation while retaining original text for comparison. Include a local playground and research verdicts.
7. Challenge cancellation, concurrent refresh, credential redirects, stalled bodies and retention races with independent tests; score synthetic consumer acceptance through 9xBench on local hardware.

The review found real defects and added regression coverage before completion. In particular, a credentialed attention request could follow a cross-origin redirect; a timeout could end before its JSON body; cancellation could leave forgetting blocked behind inference; and a superseded identity read could overwrite or relabel cached state. The updated implementation tests these boundaries explicitly.

## Integration order

Try the offline examples and browser playground first. Then install a pinned local package in one consumer and compare against that consumer's existing output. For music, retain an approved input timeline, backend version and render before changing a live performance engine. A provider adapter should pass cancellation and capability checks before a real model/hardware audition. Canonical continuity additionally needs the operator's service and access contract.

Cross-product accounts, full face-language induction, production memory storage, streaming speech orchestration and model/rig-specific integrations are outside this package's implemented contract. They remain independently reviewable work. The research report identifies model/framework candidates as watch until task-specific hardware evidence supports adoption.
