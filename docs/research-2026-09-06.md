# KAIOS SDK — 9xSweep, 6 September 2026

Research draft; no dependency adoption, publication, model downloads, or inference spend. One user-authorized bounded `fleet x` invocation was run. External runtimes and models below remain WATCH until Koto's own hardware/task benchmark passes.

**Recommendation:** build KAIOS around a small deterministic expression/state contract and portable author-controlled character data. Treat model inference, durable storage/sync, voice transport, music rendering, and visual bodies as replaceable adapters. The differentiated public project is the coherent KAIOS expression/lore/product vocabulary, not a new generic agent framework.

This is an architectural inference from several implementations and practitioner reports, not proof of a universal SOTA stack. In particular, none of the retrieved sources verifies consciousness, biological emotion, or neurological frequency claims for KAIOS.

## Cross-channel findings

### FOLD: stable contracts around changeable engines

[AIRI](https://github.com/moeru-ai/airi/blob/main/README.md) separates character stage, model providers, voice, memory components, and visual bodies. [LiveKit](https://docs.livekit.io/agents/) supports Node.js/Python realtime agents with interchangeable model plugins. [AI SDK](https://ai-sdk.dev/docs/foundations/providers-and-models) similarly isolates provider differences behind model interfaces. Independently, an [iOS character-app developer](https://www.reddit.com/r/LocalLLaMA/comments/1rxb6bz/built_an_ios_character_chat_app_that_supports/) reports separate text/image/video providers, local models and TTS, BYOK endpoints, and character imports.

**KAIOS implication:** expose a framework-independent domain layer with versioned character manifests, finite validated expression values, events/snapshots, and explicitly optional capabilities. Keep browser APIs, transport credentials, providers, visual libraries, and heavyweight databases outside the root import. This boundary preserves Kaimoji/mobile feasibility and lets kaios-substrate own persistence without turning every SDK consumer into a hosted agent.

**Caution:** AIRI's current README marks Memory Alaya and pure browser WebGPU inference incomplete. Its popularity is evidence of interest, not evidence those subsystems are done. [AIRI issue #2449](https://github.com/moeru-ai/airi/issues/2449), opened September 2, reports a local OpenAI-compatible TTS configuration regression in 0.12.0-beta.5; comments say earlier versions worked. No independent reproduction here. AIRI is reference architecture, not a dependency recommendation.

### FOLD: inspectable, scoped, reversible memory; WATCH automatic memory frameworks

The [HN Mnemo discussion](https://news.ycombinator.com/item?id=48389586) raises context pollution, hidden state, contradictory facts, forgetting, and multi-agent write governance. Its author distinguishes fast retrieval measurements from the unanswered question of whether retrieved content improves model behavior. A participant prefers project-scoped Markdown; another argues curation matters. This is useful disagreement, not a vote proving all memory systems fail.

[Automerge's documented design](https://github.com/automerge/automerge) provides a credible local-first sync option, but CRDT conflict resolution does not decide which contradictory character/lore facts are true. [Portable AI Memory](https://github.com/portable-ai-memory/portable-ai-memory) is a small interchange proposal (8 stars; no releases in this snapshot), not an established universal standard.

**KAIOS implication:** author-owned canon and versioned JSON/Markdown first; explicit record scope, provenance, revision/export, user edit/delete, bounded retrieval, and a separate adapter for durable storage. Treat generated recollections as candidate observations with provenance rather than silently revising canon. Defer cross-device CRDT sync until a concrete multi-writer need justifies its migration, conflict, and footprint cost.

### FOLD: voice lifecycle contracts; WATCH any particular voice stack

The [HN sub-500 ms voice discussion](https://news.ycombinator.com/item?id=47224295) and its [author's implementation write-up](https://www.ntik.me/posts/voice-agent) identify streaming, end-of-turn handling, cancellation, buffering, and geography as material. The author's 400 ms result is for his deployment, not ours. Discussion disagrees on modular STT→LLM→TTS versus end-to-end speech; preserve room for both. [LiveKit pipeline hooks](https://docs.livekit.io/agents/logic/nodes/) offer an existing modular implementation reference.

A fresh [LiveKit 1.8.0 issue #2430](https://github.com/livekit/agents-js/issues/2430), opened September 6 by an independent reporter, includes a deterministic reproducer for a previously paused, unplayed reply resuming while nonempty provisional input awaits the final transcript. The reporter carefully distinguishes SDK frame forwarding from telephone audibility. It is an unconfirmed upstream report here, not a verified KAIOS defect.

**KAIOS implication:** `start/stop/dispose`, cancellation propagation, clear ownership of audio, and explicit provisional-versus-committed turn state belong in the adapter contract. Stale completions must not reactivate an interrupted expression or play audio. A fake provider can test those invariants before any model is chosen.

Crucially, the showcased path uses regex commands, not an LLM; it cannot substantiate full conversational latency. Commenters also report hardware and packaging tradeoffs.

### FOLD: portable character/lore data; WATCH CCv3 interoperability until round-trip tests

The [CCv3 specification](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md) defines character metadata, lorebooks, extensions, assets, JSON and CHARX containers. JSON is a sensible first interoperability target; archive/embedded-asset import is a separate implementation problem. Preserve unknown extension data and report lossy transformations. The spec repo's last push is July 2024; a stable interchange spec need not have application-like release cadence.

**KAIOS implication:** version KAIOS's own canonical manifest and distinguish author lore, runtime expression state, user memory, and provider configuration. An importer may map CCv3 into that manifest while preserving the original source. Imported prompts, regex, asset URLs, or embedded code remain untrusted data; import should not execute code, fetch remote assets, or upgrade their instructions to host authority. Do not claim full CCv3 compliance from a name/personality mapper.

### FOLD: explicit authored expression; WATCH render engines behind adapters

[Tone.js](https://tonejs.github.io/) documents musical transport, scheduling, instruments, and signal ramps; [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices) documents user-gesture audio activation and user controls. These support an implementation pattern, not an empirical mapping from emotion to sound. Use explicit authored mappings from expression values to musical/visual parameters and describe them as artistic choices.

A [Tone Safari issue](https://github.com/Tonejs/Tone.js/issues/911) looked current by update date but was filed in 2021; its maintainer attributes the homepage demo failure to BroadcastChannel in the example widget. It does not prove Tone 15.1.22 is broken in modern Safari. Actual device/browser checks are the next evidence needed.

## Bench gates and final verdict

**FOLD as design requirements:** deterministic and validated expression state; portable author-owned canon; provenance and user-editable scoped memory; explicit adapter lifecycles; loss-aware import/export; portable imports with no network or audio side effects. These should be established by local SDK tests/benchmarks before claiming completion. The preview introduces portable subpath imports while retaining the legacy root for compatibility; full interchange and durable-memory provenance remain future work. See the separate [implementation verification](verification.md).

**WATCH until 9xBench:** every external runtime/model/package above. Compare against a dependency-free/fake-provider baseline on KAIOS tasks. No external framework or model was adopted in this research pass.

**SKIP now:** wholesale ElizaOS/AIRI migration, a required remote memory service, hidden automatic canon rewriting, model-specific identity, claims that a deterministic mood engine demonstrates consciousness, and choosing dependencies from star/download totals alone. These are scope/architecture judgments, not claims those projects are bad.

Minimum evidence to change WATCH to FOLD:

1. Core/import: import in Node without DOM/audio/network access; fresh instances do not share state; malformed/nonfinite state rejected; subscriptions and dispose do not leak; deterministic checkpoint/export/restore and current-version round-trips.
2. Memory: no-memory versus curated-memory comparison on private KAIOS continuity/contradiction tasks; provenance and deletion work; unrelated lore does not flood prompts. Measure quality, not just lookup speed.
3. Voice: cold/warm first-audio p50/p95 and end-to-end turn latency; cancellation with late frames, overlapping/interrupted turns, failures/timeouts, and disposal; English/Japanese pronunciation and style judged on KAIOS lines; RAM/CPU and model/runtime versions recorded. Do not transpose Reddit demo timings.
4. Rendering: physical Safari/Chromium device playback with explicit activation, mute/stop/dispose, suspend/resume, repeated mount/unmount, and long playback. Measure scheduling/frame cost and validate mobile package footprint.
5. Interchange: fixture round-trips including Japanese, kaomoji, multiline lore, unknown extensions, malformed input, and rollback to original source bytes. No unrequested remote asset fetch or execution.

The implementation team owns these checks. This report supplies research hypotheses and source evidence, not fabricated benchmark results.
